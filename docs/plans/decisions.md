## 自有视频与外链处理理解

### 自有视频

用户提供原始文件 → 本地准备播放版 MP4 与封面 → 记录稳定视频 ID、元数据及媒体对象键 → 静态目录供前端读取 → MediaResolver 解析到本地演示地址 → 原生播放器播放。

设计基线建议 H.264/AAC、faststart 与保留比例缩放；具体处理参数在样例测试后决定。原片与播放版分开，授权材料不进入公开目录。当前不需要建设 Web 上传后台、远程 Bucket 或转码服务器；“用户提供文件”与 V0.2 的浏览器直传是不同阶段。

未来部署时播放版与封面进入独立媒体存储，原片保持私有备份；目录保留 provider/object_key，不绑定永久 CDN 地址。需要受限访问时由媒体层执行验证，不能仅靠页面遮罩。

### 外部网站链接

保存经校验的来源地址、平台标识、外部视频 ID，以及本站标题、分类等元数据；不下载、不转码、不重托管第三方视频。不保存任意 iframe HTML，也不把网页地址作为 video src。

已核验支持且允许嵌入的来源使用官方 Embed 与对应适配器；不支持、禁止嵌入或失效的来源保留原站链接并显示降级状态。播放能力逐平台声明，无法可靠暂停的嵌入在离屏时卸载。封面仅使用有权使用的素材。

实际平台清单尚待用户提供代表性链接。外链能否嵌入不能仅凭 URL 或文档中的平台示例认定。

### 外链首轮实现（2026-11-06）

静态目录支持 `source: {"kind":"external","url":"https://example.com/watch/test"}`，与原生 HLS 条目共用标题、作者、标签、发布状态和详情路径。只接受 HTTPS 且不含账号密码的来源地址。信息流展示来源域名和「Ver en el sitio original」按钮，新标签页打开；不自动请求第三方页面，不生成 iframe。平台标识、外部视频 ID 在确定真实来源适配器时补充，当前不重复存储可从地址推导的信息。

默认目录继续保留三个合成视频；example.com 仅用于拦截目录的浏览器测试，不作为真实内容发布。真实来源尚未提供，因此未宣称支持第三方站内播放。构建和外链浏览器检查已通过（卡片、移动端宽度、跳转属性、危险协议/含凭据地址拒绝）。

### YouTube / X 官方嵌入（2026-11-06）

用户提供实际 YouTube Shorts、watch 和 X status/video 链接后，增加官方播放器适配。YouTube 解析白名单域名与 11 位 ID，使用 youtube.com/embed；携带真实页面 origin 和 strict-origin-when-cross-origin referrer policy。X 解析数字帖子 ID，在本站隔离 iframe 内加载官方 widgets.js/createTweet。任意外链仍只提供原站跳转。仅可见条目挂载 iframe，离屏或页面隐藏时卸载，避免隐藏副本及后台播放；播放器控件不由本站交互栏遮挡。

测试：构建通过；移动端三个实际条目均仅挂载一个 iframe，滑动卸载通过。两个 YouTube 条目返回官方播放器，但这不等于视频实际播放成功；X 示例官方嵌入返回「No se encontró」，未确认原因，不能判断为原帖已删除。所有条目保留原站入口，未下载或重托管媒体。

参考：https://developers.google.com/youtube/player_parameters ，https://help.x.com/en/using-x/how-to-embed-a-post 。

### 本地 Studio 原型（2026-11-06）

用户继续推进下一阶段，先复用离线工具建设 `/studio` 本地管理界面。文件上传先生成草稿，预览后明确发布；编辑、撤下/恢复和刷新签名都通过同一CLI锁执行。默认本机存储，可选已配置Tigris/HF或简单分组分配。

这是V0.2的本地交互能力，不代表Supabase管理员认证、生产权限或公网部署已经完成。API仅开发服务挂载并校验本机来源及会话令牌；一次一个任务，重启中断明确标记失败，不自动重复上传。具体操作见 docs/runbooks/local-studio.md。
